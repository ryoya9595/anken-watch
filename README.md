# anken-watch（案件ウォッチ）

クラウドワークスの新着案件から、**条件に合うものだけ**を毎朝LINEに届けるキット。
RISE生など、クライアントワークで案件を探している人に配る前提。

**解説ページ： https://ryoya9595.github.io/anken-watch/**

## 方針

- **全部転送しない。** AIが条件で選んでから届ける（1回3件が基準）
- **条件は導入時にAIがヒアリングして決める。** 白紙で「どんな案件が欲しい？」と聞かない
- 条件に合うものが無い日は送らない
- 既存のLINE公式アカウント（エルメ／Lステップ）には触らず、**通知専用を新規に作る**
- クラウドワークスへの応募・提案はしない（見るだけ）

## 構成

```
Claudeのクラウドルーティン（cron・毎朝）
   ↓ WebSearch でURLを集める（サイトを巡回しない）
   ↓ seen.py --filter  ★中身を読む前に既知を外す（読む件数を減らすため）
   ↓ WebFetch で残りを読む（1回15件まで）
   ↓ 条件で選ぶ（AIの判断）
   ↓ send_line.py
   ↓ seen.py --commit（送信が成功したときだけ）
```

| 読む順番 | ファイル | 誰が |
|---|---|---|
| 1 | `はじめにお読みください.md` | 人 |
| 2 | `事前準備ガイド.md` | 人（LINE・GitHub・Claude環境） |
| 3 | `導入手順_AIに読ませる.md` | AI（Claude Code / Codex） |
| — | `案件条件ヒアリングシート.md` | AIが導入時に使う |
| — | `導入をサポートする人へ.md` | 設置してあげる人 |
| — | `kit/` | 相手のリポジトリに置くもの |

## 開発

```bash
python3 dev/test_seen.py
```

URLの正規化（クラウドワークス／ランサーズ／ココナラ）、filter→commit の2段階、
古い記録の間引き、壊れたJSONからの復帰を検証する。ネットに接続しない。

配布Zipを作り直す：

```bash
bash dev/build_zip.sh
```

## 仕様メモ

- **filter → commit の2段階**は、LINE送信が失敗した回の案件を次回もう一度通知するための仕組み。
  送信前に commit すると、その案件が二度と通知されなくなる。**順序を変えないこと**
- 案件URLは正規化してから記録する（クエリ・末尾スラッシュ・httpの違いを吸収）
- 記録は120日で自動的に間引く（案件は流れるため）
- `state/seen.json` はルーティンが commit して push する。push できない環境でも動く（たまに重複するだけ）

## 前提の制約

- 🔴 **Claude の Pro / Max / Team プランが必要**（クラウドルーティンを使うため）。無料プランでは動かない
- クラウドワークスの公式RSSは**現在機能していない**（2012年に告知はあるが、どのURL形式でもHTMLが返る。2026-09-19 実測）
- 利用規約（第23条）にスクレイピングを名指しで禁じる条項は無いが、「利用・運営に支障を与える行為」の禁止はある。
  そのため**巡回はせず、検索で見つけたページを1回15件まで読む**設計にしている
- 公式アプリに「検索条件保存の新着案件プッシュ通知」がある。LINEに集約したい人向けのキット、という位置づけ

## 拡張

`routine-prompt.md` の検索例にランサーズ・ココナラを足せば、そのまま対象を広げられる
（`seen.py` は3サイトのURL正規化に対応済み）。
